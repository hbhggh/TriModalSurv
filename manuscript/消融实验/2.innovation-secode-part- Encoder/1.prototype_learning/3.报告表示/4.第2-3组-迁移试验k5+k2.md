## 第 2 组：策略筛选与择优

### 2.1 触发唤起

T（第 1 组）有两条：

- 报告被冻结编码器整体池化成一个向量。只换文本表示，同一模型的 C-index 在 LGG / UCEC 上能差 0.079，是纯噪声期望极差的 2.4–2.8 倍。
- UCEC 上，用从报告抽出的要素做 Cox，比模型高约 0.09。这只是单癌、单划分的结果，只作线索。

候选策略：

- k1：逐句注意力聚合
- k2：结构化字段作为独立 token
- k3：LoRA 生存适配
- k4：报告与切片的冗余感知融合
- k5：token 级融合

### 2.2 供给排查（P_i × S_state）

| 候选 | 自身前提 P_i | 当前状态 | 结论 |
|---|---|---|---|
| k1 逐句注意力 | 逐句特征；可变长的句子袋；多 token 融合 | 没有逐句特征；OCR 文本断句噪声大；融合层只接 1 个 token | 留作后备（工程量较大） |
| k2 字段 token | 逐字段文本；逐字段特征；多 token 融合 | 逐字段文本已有：`experiments/I06_llm_condensation/results/i06-condense-20260926/raw/full-struct.nolimit.jsonl` 的 `payload`，2506 人，`text_sha256` 与冻结文本逐条一致；逐字段特征需在服务器提取（短文本，成本低）；融合改动与 k5 共用 | 可行 |
| k3 LoRA 适配 | 每折只在训练集上微调编码器；防泄漏 | 算力和调参成本高；改了编码器，按公平检验基线也得同样微调 | 刷掉 |
| k4 冗余感知融合 | 报告与切片冗余的证据；把 PIBD 等代码适配到文本 | 冗余缺口没有验证过；适配成本高 | 刷掉 |
| k5 token 级融合 | 多 token 输入与逐 token 掩码 | WSI 已是 128 个聚类中心；RNA 是 BulkRNABert 按官方基因表顺序截取的前 2048 个基因 token（未筛选）；`src/trimodalsurv/models/npjc.py` 的单 token 假设集中在第 24–26、53–68、90–125 行；原型补偿器只支持单 token | 可行，但单独做胜不过 MMP / SurvPath |

所有候选共用的前提（评测协议）：**5 折交叉验证现在还不能直接跑。** 现有训练管线有三处缺陷，任何一处都会让结果静默出错：

1. 数据缓存键只由 split 名、`img_select` 和癌种组成（`src/trimodalsurv/data/tcga_dataset.py` 第 87–94 行），不含标签文件哈希，也不含文本档案。
   - 按折换标签文件时，会静默复用上一折的缓存：新进入该折的病人被当成 RNA 缺失，并且会覆盖默认缓存。
   - 不同文本档案共用一个缓存时，会静默读到别的档案的文本。
2. 训练和评测进程的工作目录都是 NPJ_ROOT（`scripts/train_launcher.py` 第 784、916 行），`--cache-dir` 只对预热生效。
3. ckpt 路径不含折号（`scripts/train_launcher.py` 第 542 行），而第 811 行遇到已有 ckpt 就跳过训练。后面的折可能直接用上训练时见过本折病人的模型，造成泄漏。

相关坑：D2（规则里要求缓存键纳入标签 hash，但没有实现）、D15、I05-13。修法见 3.2 第 2 条。

### 2.3 边界择优

胜出：**k5 + k2**。k5 是基础设施，k2 是要检验的机制。

Boundary（在当前情境下为什么选它）：

1. **对准最可信的文本现象。** 只换文本表示，LGG / UCEC 上就能差 0.079。k2 把报告里的预后要素拆成独立 token，改的正是「报告怎样变成表示」这一环。
2. **用成熟方法改造。** 每个字段一个 token、再加字段类型嵌入，是表格 Transformer 的成熟做法；token 级多模态融合是 MMP / SurvPath 的成熟做法。改造只落在「报告字段」这一处。
3. **公平检验内置。**
   - V2 与 C1 的内容相同，都是 LLM 结构化后的字段。两者的差别有三处：逐字段单独编码、token 数（中位数 LGG 7 个、UCEC 11 个，而 C1 只有 1 个）、字段类型嵌入。
   - C2 用和 V2 相同的逐字段向量，先取均值压成 1 个 token，所以 V2 − C2 只剩「多 token 加字段类型嵌入」这一个差别。
   - 全部臂都用同一个 NeuML 编码器。
4. **成本可控。** 数据、划分、特征全部复用，新增的只有逐字段特征提取、融合层改动和按折隔离。
5. **k5 单独做不胜出。** 在新主判定下，只做 k5 等于采用现成的 token 级融合，所以在本试验里它是骨架 V1。

## 第 3 组：锁定 P_specific + Q_specific（草案 v2）

### 3.1 臂

| 臂 | 融合 | 文本 | 作用 | 出现在 |
|---|---|---|---|---|
| V1 | k5 token 级融合 | B2：NeuML 全文编码，1 个 token | 所选骨架；方法变体 1 | 交叉验证、最终确认 |
| V2 | k5 + k2 | 逐字段 token（NeuML 逐字段编码，加字段类型嵌入） | 要检验的方法；方法变体 2 | 交叉验证、最终确认 |
| C1 | k5 | A1-S：结构化文本整段编码，1 个 token | 最相关方法的代表（LLM 结构化 / 摘要一类） | 交叉验证第 2 段、最终确认 |
| C2 | k5 | 逐字段向量取均值，1 个 token | 机制对照：分离多 token 的作用 | 交叉验证第 2 段、最终确认 |
| V0 | NPJ-C 现骨架 | B2 | 现骨架参照 | 只在最终确认时出现，用已有的 B2 正式预测（同样的 test 与 seed） |

方法变体只有 V1、V2 两个，符合止损上限；C1、C2、V0 都是对照。PS3 的段级选择要适配后才能加入，不在本轮范围内。

### 3.2 P_specific（前提锁定）

**1. 数据与划分**
- 标签 CSV、病人、特征都不变。
- 发现阶段只在固定划分的 train + valid（60% 的病人）内部做五癌 5 折分层交叉验证：
  - 按癌种 × 事件分层，随机种子 20260929；
  - 每一轮 3 折训练、1 折选轮（valid）、1 折评估，共轮换 5 次，每个病人恰好被评估一次；
  - 折文件是新建文件，写明 sha256，先过坑 D1 的检查（patient_id 唯一、各 split 两两不交）；
  - 固定 test（40%）不进任何折文件，所以训练入口即使无条件在 test 上预测，也碰不到它（坑 V31）。
- 最终确认：只有发现阶段通过，才在固定划分上训练，并用固定 test 只跑一次；授权要绑定 ckpt 集合（坑 V35、V36）。

**2. 按折隔离（核心逻辑，先写测试，并在旧代码上确认测试会失败）**
- 缓存：每个「折 × 文本档案」一个独立的运行根，`<可变资产根>/<run>/fold<k>/<档案>/tmp_sur_cache`，缓存目录本身的 basename 必须是 `tmp_sur_cache`（坑 I05-13）。
  - 训练和评测进程的工作目录都要指向这个运行根，不能只改 `--cache-dir`。
  - 独占预热后再并发（坑 D15）。
  - 默认的 `tmp_sur_cache/` 不动。
- 成员校验：加载缓存时逐个模态核对，缓存里的病人集合必须等于「该折名单 ∩ 源文件里有该模态的病人」，不等就报错。不能只做子集校验。
- ckpt：路径里包含折号与档案。「已有 ckpt 就跳过」的逻辑要绑定该折标签文件的哈希，换折即拒绝。
- 这三处缺陷在写研究计划书时补进坑台账。

**3. 逐字段文本特征**
- 来源：上面那份 `payload`，字段键见 `experiments/I06_llm_condensation/model.py` 第 45–99 行。每个字段的文本就是冻结序列化时用的那句「字段名: 取值.」（同一文件第 194–209 行）；缺失的字段在 C1 和 V2 里都被省略，两边内容等价。
- 编码：与 B2 同一个 NeuML 模型、同一种池化（有效 token 取均值），每个字段得到一个 768 维向量。缺失的字段不产生 token，用掩码处理。
- C1 的整段特征在同一个作业里重新提取，并用 allclose 与现有 A1-S 特征核对。
- 在服务器上经 landau 的 `jobrun.sh` 提取。全部输出都断言形状、类型、有限值，并写 manifest 与 sha256（坑 D6）。
- TCGA-EC-A24G（结构化抽取为 fallback_empty，在 UCEC 训练池里）在交叉验证的所有臂里一律按「文本缺失」处理，避免出现 0/0。

**4. 模型改动（`npjc.py`，核心逻辑，先写测试）**
- WSI 的 128 行作为 128 个 token，按行掩码，补零的行不参与。
- 文本 token 数可变，带掩码；V2 的每个字段 token 加一个可学习的字段类型嵌入。
- RNA 仍按现骨架压成 1 个 token。本试验不动 RNA，控制变量。
- 模态嵌入按模态广播到该模态的所有 token。
- 池化：先在每个模态内对有效 token 取均值，再对有效模态取均值，与现骨架的模态等权保持一致。
- 其余超参数沿用现骨架：hidden 256、4 头、1 层、dropout 0.1、lr 1e-4、50 轮、batch 32，按 valid C-index 选轮。发车参数逐项对齐（坑 D16）。
- 缺失场景只评 m0real（整个模态掩码）。原型补偿器只支持单 token，本试验不评 Proto。

**5. 流程**
- 研究计划书 → Codex 节点一审查 → candidate → 冒烟 → squash → freeze → 用户授权 → 发现阶段 → 节点二审查 → （通过后）用户再授权固定 test 确认。
- NPJ 的 GPU 利用率豁免在模型显著加大后失效（AGENTS.md「正式实验 GPU 合同」第 7 条）。冒烟时重测，仍低于门禁就交用户裁决。

### 3.3 Q_specific（数值写死）

**统计口径（发现阶段与最终确认共用）**
- 在每个评估集内，每个 seed 分别算 Harrell C。先对 seed 取平均，再对折取平均，得到每个癌种的 C；五个癌种等权平均，得到 Overall。
- 配对差 ΔC 的 95% CI 用两层 bootstrap（1000 次，同一次重抽贯穿所有臂）：
  - 在「折 × 癌种」内重抽病人；
  - 在每折内有放回地重抽 seed，把训练随机性也算进去。

**功效说明（事先写明）**
- 审查员用现有预测估算：LGG + UCEC 的 74 个事件、3 个 seed，配对差 CI 半宽为 0.036。
- 五癌交叉验证的评估事件约为 400 个（test 的 268 个 × 1.5）。按事件数折算，预计半宽约 0.015（粗算，没有计入 seed 数增加带来的收窄）。
- 所以本设计能检出的最小效应大约是 0.015–0.02。真实效应更小时会落在「证据不足」，这是事先承认的设计局限。

**发现阶段，分两段执行**

第 1 段只跑 V1 与 V2（2 臂 × 5 癌 × 5 折 × 5 seed = 250 次训练）。按顺序判定 ΔC(V2 − V1)（none 场景，Overall）：

1. **判否（方向相反）**：点估计 < 0，且 CI 上限 < 0。
2. **证据不足**：CI 半宽 > 0.02。
3. **进入第 2 段**：同时满足以下三条——
   - 点估计 ≥ +0.01，且 CI 下限 > 0；
   - 至少 3/5 个癌种的 ΔC 为正；
   - 底线：text_100 / rna_100 / both_100（m0real）三个场景的 Overall ΔC 点估计都 ≥ −0.01。
4. **判否**：其余情况。

判否或证据不足时就停止：声明 Q_new，回到约束清单复盘。是否试 k1 由用户决定。

第 2 段补跑 C1 与 C2（再 250 次训练），判定：

- **发现成立（可申请固定 test 确认）**：ΔC(V2 − C1) ≥ +0.01 且 CI 下限 > 0，即胜过最相关方法的代表。
- **机制解释（不作继续条件）**：
  - ΔC(V2 − C2) 的 CI 下限 > 0：记为「多 token 本身有效」；
  - 否则：记为「增益主要来自逐字段编码」；
  - 论文按实际情况措辞。
- 其余情况：判否，停止。

**最终确认（固定划分，test 只跑一次）**
- 在固定 train 上训练 V1、V2、C1、C2，用固定 valid 选轮，seed 用 123 / 132 / 213 / 231 / 321；V0 用已有的 B2 正式预测。
- 确认成立：ΔC(V2 − V1) 与 ΔC(V2 − C1) 的 Overall 点估计都 > 0（方向与发现阶段一致），并且 ΔC(V2 − V1) 的 95% CI 下限 > −0.01（不劣于骨架）。
- 同时报告 ΔC(V2 − V0)，以及对 Table 1 Proto. 严格胜的癌种数 k/5（参考项）。
- 确认不成立：如实报告，不换数据、不重跑。

**止损**
- 方法变体不超过 2 个，不做超参数搜索。
- 算力预算：按现有记录，单次训练约 5 分钟。
  - 第 1 段：250 次训练，预算不超过 30 卡时；
  - 第 2 段：再 250 次，预算不超过 30 卡时；
  - 按折 × 档案重建缓存：不超过 15 CPU 小时；
  - 每段授权后 3 个工作日内出结果；超出预算即停下交用户。

### 3.4 已知风险

- **中心捷径**：随机分层交叉验证与原划分一致，各臂受到同样的影响，配对比较能部分抵消；论文的局限部分需要说明。
- **RNA 表示**：RNA 分支按官方基因表顺序截取前 2048 个基因，未筛选。本试验不改，结论只适用于这一种 RNA 表示。
- **字段质量**：逐字段特征的质量取决于 LLM 抽取。此前抽查 40 份，幻觉 2 份、遗漏 2 份。
- **混杂**：k5 顺带修掉了「WSI 补零行被平均进去」的问题，这只影响现骨架参照 V0 的比较；所有判定都在 k5 内部进行（V2 对 V1 / C1 / C2）。
- **功效**：见 3.3，真实效应小于 0.015 时大概率「证据不足」。
