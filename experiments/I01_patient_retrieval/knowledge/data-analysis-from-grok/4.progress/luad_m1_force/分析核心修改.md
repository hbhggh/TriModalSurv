# 分析核心修改：S0-force（仅 LUAD 路由）

| 改了哪一函数／文件 | 3.progress 旧行为 | 4.progress 新行为 | 影响场景 | 与其他规则关系 |
|---|---|---|---|---|
| `model.py:route_patient` | 仅当 valid 的 `B>A` 时，LUAD 路由才生效；非 LUAD 无区分地返回组合。 | LUAD 路由表不变但默认强制有效；非 LUAD 输出 `route=upstream_combo` 与 `strategy0_enabled=null`。 | LUAD 四场景；非 LUAD 仅审计字段。 | 不改 λ=1、α=1、w=0.5 或 UCEC 例外。 |
| `run.py:force_freeze` | `enabled=(B>A)`，已观察到 B−A=−0.008815 时关闭。 | 始终输出 JSON 布尔 `enabled=true`；valid A/B 仅审计。 | 冻结文件与 LUAD test。 | 唯一科学变更；构成 test 泄漏。 |
| `run.py:_valid_reference_rows` | 3.progress 自行真实计算 valid B 后由其门禁决定。 | 只复用 3.progress 已在 `enabled=true` 下生成的 valid B，哈希不符即报错；禁止复用 3.progress test。 | valid 审计。 | 不把协议名导致的运行指纹差异误判成输入不一致。 |
| `run.py:_compare_luad_fixed_routes` | 只检查新 test 与 3.progress 不是完全相同。 | `rna_100`／`both_100` 必须逐 logit、逐 C-index 等价 m1；`text_100` 等价 m0real；`none` 保留逐患者路由计数。 | LUAD test。 | 满足 Claude C1；不把任意一格变化误当整表生效。 |
| `run.py:annotate_reused_combo_row` | 非 LUAD 复用行写作 `strategy0_enabled=false`。 | 写作 `strategy0_enabled=null`，表示该癌不适用 S0-force。 | 非 LUAD 80 格组合。 | 满足 Claude C2；固定 m1/m0 数值不变。 |

## 不变项

- 25 个 E0/NPJ-C checkpoint、45 份缓存、split、K=128、B 口径、患者库、CAP 状态、模型 state_dict 均不改。
- 非 LUAD 组合与所有固定 m1/m0 逐格只读复用 `2.progress`；不重算、不挑 test 参数。
- 路由提升若存在，只能称为“LUAD 按场景切换到固定 m1/m0real”的探索性反事实；不是患者检索机制成立。
