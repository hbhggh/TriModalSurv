**不是实现写错，是门禁把刀关了。** Valid 上 LUAD 走 m1 比冻结组合差 0.0088，开关 `enabled=false`，test 等于 2.progress 原表，所以还是 3/5。

## 发生了什么


| 层     | 事实                                                                         |
| -------- | ------------------------------------------------------------------------------ |
| 代码   | `route_patient`、LUAD 只重算 20 格、非 LUAD 哈希复用，与计划一致             |
| valid  | A（组合）**0.654042** > B（strategy0 强制开）**0.645226**，Δ **−0.008815** |
| 冻结   | `B 严格 > A 才启用` → **关闭**                                              |
| test   | `strategy0_enabled: false`；LUAD 四场景仍是组合，不是 m1                     |
| 癌种胜 | BRCA/LGG/UCEC 胜，LUAD/BLCA 未胜 →**3/5**                                   |

`complete.json` 里 LUAD 20 格全部 `"strategy0_enabled": false`。失败格（rna_100 / both_100）根本没换成 m1。

## 三层原因（主因是设计）

**1. 实验设计（主因）**
4/5 的算术是用 **已见 test** 算的：LUAD 若 none/rna/both=m1、text=m0，均分会过双基线。
门禁比<span style="color: #ff0000;">的是 valid 上 B 对 A（组合），不是 test，也不是对 m1/m0。</span>
Valid 上组合检索 RNA **有用**，改 m1 会掉 0.009 → 按规定必须关。
这是「用 test 想刀、用 valid 否决」的符号相反，不是漏跑。

**2. 代码（次因，且按计划）**
`freeze_valid_switch`：`enabled = (b_mean > a_mean)`。valid 阶段 `enabled=True` 只为算 B；test 吃冻结值。逻辑对。
`route_patient` 在 `not enabled` 时一律 `upstream_combo`。没有把 LUAD 误路由。

**3. 结果（符合关闭后的恒等）**
100 格 0.640155、LUAD 0.585284，与 2.progress 组合逐格相同。报告写 3/5 是对的。

用现成 **test** 反事实（门若开着）：


| LUAD 场景 | 现（关=组合） | 若开                   |
| ----------- | --------------- | ------------------------ |
| none      | 0.582485      | **m1 0.583819**        |
| rna_100   | 0.577290      | **m1 0.580239**        |
| text_100  | 0.596630      | m0 0.596630（本来就=） |
| both_100  | 0.584731      | **m1 0.588803**        |
| 四场景均  | 0.585284      | **≈0.587373**         |

相对 m1 0.587004 → 约 **+0.00037**；相对 m0 0.586206 → 约 **+0.00117**。
**若强制开，这一份 test 会 4/5。** 间隔极薄，且 valid 明确反对。

BLCA 仍然动不了：rna_100 赢家是 m0，λ/m1 都到不了。

## 要 4/5 怎么改（只动门，不重训、不扩 seed、不动 BLCA）


| 方案                     | 做什么                                                                               | 4/5                          | 代价                                      |
| -------------------------- | -------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------- |
| **S0-force（最小、灰）** | 作废「B>A」否决；**强制启用** 已实现的 LUAD 路由。valid 只审计（已有 B−A=−0.0088） | 对本份 test**期望 4/5**      | 明文：valid 反对、规则来自旧 test，非盲测 |
| S0-gate2                 | 开关改成 valid 上**B 同时严格 > m1 且 > m0**（对齐癌种胜），不再要求赢组合           | 未知（缺 valid 的 m1/m0 表） | 比 force 稍能讲；valid 上仍可能 B<A       |
| 维持现状                 | 门禁保持                                                                             | 就是 3/5                     | 学术上最干净                              |
| 动 BLCA / 扫 λ / 多种子 | —                                                                                   | 不保证                       | 禁止当本轮补丁                            |

**不要改路由表本身**（text=m0、rna/both/none 缺 RNA=m1、w=1 对齐固定 m1）。错的是「谁有权关掉它」。

## 拍板

- 代码和复用哈希：**通过**；3/5 不是算错。
- 4/5 没到，是因为 **valid 与 test 在 LUAD 上符号相反，门按字面关掉了策略**。
- 还要 4/5：只改冻结规则为 **强制启用**（S0-force），test 再跑一次 LUAD 20 格（`enabled=true`），非 LUAD 继续复用。postcondition 必须写：`valid B−A=−0.008815 仍启用；4/5 若达成不可写成检索赢了`。
- 停：不改 BLCA、不重扫 λ、不扩 seed。
