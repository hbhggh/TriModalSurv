## 0. 结论

模态优先级是 **Text > RNA > WSI**。

- **k1**：用长上下文、嵌入型的文本编码器读完整病理报告，输出 768 维，属层级①。
- **k2**：在 k1 之前加一步，先用 LLM 把报告浓缩，再做嵌入。

两者都要重训 25 个 NPJ-C checkpoint，并在新文本空间重建检索库；动用训练需要用户另行授权。没有看到能支持"保证 4/5"的证据。

**test 防火墙声明**：这个排序只依据外部文献和接口成本得出。第 3 节"补充三"列出的 test 去模态数字只是描述性背景，没有参与择优；把它们删掉，排序不变。

#### k1-Qwen3-Embedding｜长上下文嵌入型文本编码器读完整报告

实例：Qwen3-Embedding-0.6B，用 MRL 直接输出 768 维。

**机制与来源**

机制有两点：

- 覆盖。模型有 32k 上下文，能读完全文。TCGA 最长的报告是 8,184 token [1]。
- 池化目标匹配。对比学习训出来的嵌入器输出单个向量，本来就是为线性下游设计的，与"冻结特征→mean→Linear"这个接口一致。

来源：权重开源，Apache-2.0，支持自定义 32–1024 维 [W4]。

直接任务证据：

- [1] 使用的是同样的三元组：UNI2-h、BulkRNABert、TCGA-Reports。在这五癌上，文本单模态的 C-index 是 BRCA 0.641、UCEC 0.723、LGG 0.716、LUAD 0.645、BLCA 0.576。它的协议是冻结嵌入→PCA→CoxPH、5 折交叉验证，与本项目不同，数值不能直接比较。
- [2] 去掉报告后，平均 C-index 从 0.699 降到 0.644。把文本编码器从 PLIP 换成 QUILT-Net，平均变化 −3.29%。
- [3][4] 同方向佐证。

间接依据：

- 长序列临床模型系统性优于 512 截断的模型 [8]。
- LLM 表示优于旧式嵌入 [21]。

需要明确的一点：**"Qwen3-Embedding 能提升病理报告生存预测"没有直接证据，这是迁移推断。**

**P × S_state**

- 已满足：
  - 768 维，形状不变。
  - 许可证和权重可得。
  - 不动 E1 的 key。
- 未核实：见 A 表 Text 一行。另外，服务器的 transformers 版本要满足模型卡要求（Qwen3 系列一般需 ≥4.51，这一条本次没有复核）。
- 未满足：需要重训，须授权。

**Boundary**

适用的情形：预后信息落在前 200 token 之外，或者被 token 平均冲淡。

可能无效的情形：

- 整篇被套话稀释。[1] 里未摘要 0.694，低于摘要后的 0.752。
- 信号集中在少数关键词上 [6]。
- LUAD。

**最小改动落点**

- 新建文本特征目录。单向量平铺成 `[200,768]`，可以零代码改动。或者改 `fallback_shapes` 和 config 里的 `shapes`。
- **必须使用隔离的缓存目录。** dataset 缓存的文件名里不含特征路径，AGENTS 又禁止改 `tmp_sur_cache/`。如果不隔离，会静默读到旧特征，或者污染基线缓存。
- 检索库要在新文本空间重建。key 和 donor 不变，但 μ_c^text 和 λ=1 填入的 donor 值都会变。LUAD none 每个 seed 有 5 人只缺 Text，他们会走这条路径。这是需要披露的归因混杂。

**成本**

- 提取特征：分钟到小时级。 #re
- 训练：25 次短训练。如果做成对基线重训，再加 25 次。

**公平比较的前提**

- 同代码、同配方、同 seed、同 split，只有文本特征目录不同。
- 指令前缀、维度、模型尺寸在看 test 之前固定，选择只用 valid。

#### k1-BioClinical ModernBERT 嵌入版

### k2｜k1 之前加 LLM 浓缩报告

层级仍是①。摘要器属于原始数据预处理，不引入融合或补偿。

**机制与来源**

直接任务证据全部来自 [1]，数据源相同：

- 用 Llama-3.1-8B-Instruct 摘要之后，文本单模态的泛癌 C-index 从 0.694 升到 0.752。
- BioMistral 与 Mistral 几乎相同，0.752 对 0.751。也就是说领域预训练在这里不重要，输入怎么处理才重要。
- 抽检了 40 份摘要，其中 24 份需要小修。修正之后，风险分层没有变化。

**P**

- 本地要有 instruct LLM，V100-32GB fp16 可行。Llama 需要许可，也可以换成 Apache-2.0 的替代模型。
- 用贪心解码，摘要文本连同哈希一起归档，当作冻结工件。
- 幻觉抽检要列为验收项。

**Boundary**

- 多了"摘要器"这个因素：
  - k2 对比 k1，可以单独分离出"浓缩"的效果。
  - k2 对比基线，两个因素混在一起。
- [1] 的泛癌数字里含有癌种信息，分癌种的增益没有直接验证。
- LLM 会带入先验知识。成本是小时到一天。

**适用条件**

在 k1 被套话稀释，或者希望文献背书最强的时候采用。

### 被排除项：BioClinical ModernBERT

它最贴合"BERT→ModernBERT"的叙事：

- 8,192 上下文，768 维，MIT 许可。
- 语料里含病理报告数据集 CHIFIR [9][W5]。

没有选它的原因：

- 模型卡给出的下游用法是按标准 BERT 配方微调 [W5]。它是 MLM 预训练的编码器，没有做过嵌入目标的训练。
- 在 136–383 人上微调会超出"低成本、零训练 encoder"的范围，也会破坏冻结特征库。
- [1] 里领域版与通用版没有差别。

在"现编码器身份未知"的前提下，不能断言通用嵌入器一定优于领域 MLM。上面的理由只涉及池化目标和接口。

## 6. D. 最终决策边界

**推荐 k1 的条件：**

- 五癌的原文和患者 ID 能对上。
- 用户授权 25 次重训。
- 最好再加 25 次成对的基线重训。

**k2 作为替代的条件：**

- k1 被稀释，或者想要更强的文献背书。
- 能接受摘要器带来的第二个变量。

**会改变决策的缺口只有五项：**

1. **现文本编码器身份，以及 200 行的含义。**
   最小核验办法：在服务器上统计 `text_embeddings_parsed` 里每个人的非零行数，再与原文的 token 数对照。
2. **原文是否在服务器上。**
   本机没有 `data/`。
3. **训练源码指纹。**
   - 先验知识第 47 行写明，代码快照不能冒充历史运行源码。
   - [I01 总实验 map](../../I01_patient_retrieval/results/原因分析-ai-prompt&md/patient-fixed-padmask-v2-总实验map.md) 第 428 行记着"9月15日冻结源码重建，不是训练时源码指纹"。
   - 所以，只有先复现出 Table 1 的 None 行，历史 25 个值才能当严格的单因素对照。否则只能作参照。
4. **GPU 是否可用。**
5. **噪声底。**
   - 五 seed 均值的 SE：LGG 0.0046、BRCA 0.0033、BLCA 0.0251、LUAD 0.0045、UCEC 0.0069。BLCA 的 seed213 等于 0.491，是离群值。
   - 在零真实效应下，"五癌中至少四癌严格更高"的偶然通过率约 18.8%，这是假设各癌胜负对称且相互独立时的 6/32。
   - 所以 4/5 本身是弱证据，BLCA 的胜负基本由单个 seed 决定。
   - Q 不改。建议把逐 seed 的配对差值作为补充一起报告，是否采纳由用户定。

**关于"新 BERT 几乎肯定涨点"。** 文献不支持这个判断，理由有三条：

- [1] 里领域版 BioMistral 与通用版 Mistral 几乎没有差别。起作用的是先对报告做摘要再嵌入，也就是输入的处理方式。
- 长病理报告上，BERT 类模型常不敌 CNN/HiSAN 这类简单模型 [6]。
- 加上上面第 5 条的噪声底，涨点没有保证。

 D1 上下文长度

两种设计回答的是不同问题：

- ChatGPT 的设计回答"换编码器本身有没有用"。
- 我的设计回答"把报告读全有没有用"。

**ChatGPT 的归因更干净，但有两个弱点：**

- 检出力可能偏低。
  - 仓库里有硬证：作者嵌入每人恰好 200 行，见 `parse_text_embeddings.py` 的 docstring。
  - HANDOFF 记报告中位 453 词。这句话出自未执行的"阶段 2"段落，只能当线索，不能当事实。
  - 如果属实，两臂看到的是同一段被截断的前缀，很难分出差别。
  - 它自己在第 287 行也把"200 token 截断丢掉后段信息"列为失败模式。
- 不同 tokenizer 的 200 token 覆盖的文本跨度不同，单因素并不完全干净。

**我这份的弱点更大，一次改了三个因素：**

- 编码器类型。
- 覆盖范围。
- 表征粒度。单向量平铺后，模型里的 `mean(dim=1)` 实际成了恒等操作。

第三个因素是审查员指出的，我原先漏算了。

### D2 编码器类型

双方都没有直接的生存证据：

- ChatGPT 的依据是模型卡上的**微调**基准，但它建议的用法是**冻结加 token 平均**，证据和用法对不上。
- 我的依据同样是间接推断。
- Song S. 2025 里领域版约等于通用版，但那是 7B 解码器跑摘要后的文本，不能直接外推到 BERT 级编码器。

叙事上 ChatGPT 的更贴合"BERT→ModernBERT"，而且保留了 token 级的缓存语义，不需要我那种平铺的权宜做法。
