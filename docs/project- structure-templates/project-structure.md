# 项目结构与归属

```text
TriModalSurv/
├── README.md / STATUS.md / AGENTS.md / CLAUDE.md
├── src/trimodalsurv/       # 公共模型、数据、训练、评测、配置
├── scripts/               # 公共启动与门禁
├── configs/               # 共享模型及运行配置
├── experiments/           # _template、I01–I04、基线清单、_comparisons
├── tests/                 # 公共契约与分箱回归
├── baselines/             # MCAT/PORPOISE独立实现和Git
├── docs/                  # engineering、metrics、research-ideas、workflow、assets、refactor、templates
├── manuscript/            # 自有稿件与references分开
└── archive/               # legacy_npj_snapshot、legacy_collab、legacy_docs、runtime_artifacts
```

## 分类边界

- `src/` 只保存实际共享实现，不导入实验。创新算子在所属 `model.py`，通过组合接入公共模型。
- 一个新机制建一个实验 ID；相同机制不同 seed、超参数或重跑形成独立 run，不复制公共骨架。
- `results/` 包含原始结果、来源清单与分析；`raw/` 中历史字段、路径、数值保持原样，索引解释当前位置。
- `knowledge/` 关联代码标记、文字说明、可编辑机制图及结果。旧稿在 `legacy-source/` 保留，正文与删除线不改。
- `docs/research-ideas/` 收未实现构想；`docs/workflow/` 收编辑器与知识整理方法，不混入实验方法。
- `archive/` 用于原文和历史源码溯源；生产代码不能从此导入。MCAT/PORPOISE 是保留的外部基线，不归档其活动实现。
- 历史 `STATUS.md` 正文继续保留；本次只修链接，后续只追加。

## 实验骨架

```text
experiments/<experiment_id>/
├── README.md
├── model.py
├── config.yaml
├── knowledge/
│   ├── index.md
│   └── method.md
└── results/
    └── index.md
```

ID/名称未确认不自动创建。机制确定后生成 `knowledge/method.excalidraw.svg`；真实运行开始后才创建 `results/<run_id>/resolved_config.yaml`、原始产物和 `analysis.md`。

完整来源、旧→新路径和验证范围见[本轮执行账本](refactor/20260916-080006-full-project/progress.md)。历史命令属于其记录时部署；此次本地归位不等于远端部署完成。




# 面向实验的机器学习科研项目初始化模板

> 将本文件作为 AI / Codex 的项目先验知识。它规定组织方式与证据要求，不替用户选择数据、模型或实验方向。所有 `<...>` 都是待确认占位符，不是可直接执行的值。

## 1. 使用方法

在新会话中附上本文件，并提供目标项目目录。可以直接发送：

> 请先阅读这份模板和目标项目的已有规则。先询问并确认数据、任务、已有资产、模型是否确定、运行环境与本次允许修改的范围；将已确认信息整理给我。确认后按模板初始化。保留已有文件，只新增获准内容；本次不安装依赖、不下载数据、不训练。遇到未定项要明确记录，不能用示例值替我决定。

本文件可独立使用，不需要原会话、特定项目或指定 AI 插件。复制模板不等于授权初始化；初始化不等于授权训练或迁移旧项目。已有项目先读当前规则、目录与证据；规则冲突先指出具体冲突，再确认处理方式。

## 2. 初始化前必须询问

每轮最多 3 个问题；已有明确回答不重复问，用户允许后可用只读文件核验补全事实。“已确认暂未确定”也是有效状态：模型、数据维度或实验标识尚未确定时，可在用户授权后仅建立第 8 节的空壳与待确认清单，不要求先完成科研选型。会影响当前写盘范围或资产保护的决策未锁定时，先澄清再写盘：


| 必问项       | 需要确认的内容                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| 数据         | 数据类型与位置、输入/标签含义、样本单位、已有划分、是否已有预处理或特征；未知的维度与规模标为待确认。 |
| 任务         | 要预测什么、输出语义、目标指标与比较对象、本次要验证的科学问题。                                      |
| 已有资产     | 基线代码、配置、checkpoint、结果、论文与说明文档在哪里；哪些可信、哪些必须原样保留。                  |
| 模型是否确定 | 框架、基线和创新机制各自是已确定、候选还是未定；已确定的接口与训练/推理位置是什么。                   |
| 环境与权限   | 目标目录、语言/框架与解释器、依赖现状、计算设备与运行位置；允许新增/修改哪些文件、允许何种验证。      |

另外确认项目包名 `<package>` 与实验标识 `<experiment_id>`。不得默认某个模型、数据集、seed 数量、服务器或项目绝对路径。指标方向、划分策略、超参数和正式启动权由用户确认。

确认记录使用 `[已确认]`、`[待确认]`、`[已核验：来源]` 区分用户决策与文件证据。无法从历史资料恢复的值写 `unknown`，不得补成“惯用默认值”。

## 3. 统一目录与职责

下面是目标结构说明，不是要求立即创建所有文件。实际初始化仅创建当前获准且有明确职责的部分；`<run_id>` 在真正启动获准运行时才建立。

```text
<project>/
├── src/<package>/
│   ├── data/                  # 数据读取、划分与预处理契约
│   ├── models/                # 共享基线、组件与稳定接口
│   ├── training/              # 共享训练与优化流程
│   └── evaluation/            # 共享评测与汇总逻辑
├── configs/
│   └── defaults.yaml          # 已确认的公共默认配置
├── experiments/
│   ├── _template/             # 新实验骨架；不作为真实实验运行
│   │   ├── README.md
│   │   ├── model.py
│   │   ├── config.yaml
│   │   ├── knowledge/
│   │   │   ├── index.md
│   │   │   └── method.md
│   │   └── results/
│   │       └── index.md
│   └── <experiment_id>/       # 一个创新点一个文件夹
│       ├── README.md
│       ├── model.py
│       ├── config.yaml
│       ├── knowledge/
│       │   ├── index.md
│       │   ├── method.md
│       │   └── method.excalidraw.svg  # 机制确定后才生成
│       └── results/
│           └── <run_id>/
│               ├── resolved_config.yaml
│               ├── provenance.yaml
│               ├── raw/
│               └── analysis.md
├── docs/                      # 项目约定、数据契约与跨实验说明
└── STATUS.md                  # 项目状态；已有正文只允许末尾追加
```

- `src/<package>/` 是公共实现的唯一来源。多个实验调用同一份数据、基线、训练与评测代码，不复制整套流水线。
- `configs/` 保存跨实验默认值；实验局部差异放在自己的 `config.yaml`，不散落为代码常量。
- `experiments/_template/` 只提供说明和待填写接口，不包含虚构模型、结果或已跑通声明。
- 每个创新点保留独立文件夹与结果。组合实验另建文件夹，引用已有组件；不把多个相互独立的创新点堆进一个不断扩大的 `model.py`。
- `docs/` 保存公共知识；具体创新机制与证据放到对应实验的 `knowledge/`。未知或未实现部分必须明确标记。

## 4. 一个创新点里写什么

### `README.md`：入口

简短写清：科学问题、假设、所依赖基线、相对基线只改变什么、当前状态、文件入口与已存在的证据链接。区分“设计完成”“实现完成”“冒烟通过”“正式结果”；命令只有在真实入口存在且已核对后才记录，不填看似可用的命令。

### `model.py`：实际创新与组合

公共基线和组件从 `src/<package>/` 导入，实际新增算法在本文件中用注释标记：

```python
# INNOVATION-BEGIN: <创新机制名称及其输入/输出>
# 在机制和接口确认后，将真正新增的运算实现放在这里。
# INNOVATION-END
```

上述片段只说明标记方式。标记要包住真实新算法；只有导入或一行调用不能声称已实现创新。复用另一个实验的创新组件时，标出其实现路径与版本，不再复制一份。

组合注入必须明确位置，例如“基线的 `<前序模块>` 输出之后、`<后序模块>` 输入之前”。同时记录输入/输出张量或结构、mask 含义、维度变化、训练时与推理时是否启用、是否增加参数或损失。机制只作用于训练、损失或数据处理时如实说明，不能虚构 forward 中的注入位置。

### `config.yaml`：实验差异

只记录本实验相对公共默认的覆盖项，并注明引用的默认配置。参数名与实际构造接口一致；候选值和待定事项留在说明中，不冒充正式运行值。

### `knowledge/index.md`：知识索引

链接 `method.md`、已核验论文/代码来源、机制图和相关结果分析；每个来源标明支持哪项机制或判断。不把设计解释当成运行证据。

### `knowledge/method.md`：机制说明

写清“输入 → 操作 → 输出”、创新点、对应代码符号、训练/推理路线、与基线的关系、局限与待定项。形状类比和论文复现分开表述，论文机制与本项目实现有差异时直接列出。

机制确定后才生成 `knowledge/method.excalidraw.svg`；必须保留可编辑的 Excalidraw 场景数据，并在目标编辑器验证能重新打开、编辑和保存。普通 SVG 改名不算可编辑文件。机制未定时只记录待生成原因。

## 5. 参数必须对应真实运行

配置优先级固定为：

```text
公共默认 configs/defaults.yaml
    → 实验 experiments/<experiment_id>/config.yaml
    → 用户显式提供的 CLI 参数
```

CLI 未显式提供的参数不得覆盖 YAML。将“未传入”与 `false`、`0`、空字符串及显式空值区分；使用参数是否出现的记录或专用哨兵，不能依靠真值判断。未知键、拼写错误和未消除的必填占位符必须阻止运行。

真正获准运行时：

1. 合并配置并逐项保存值来源，冻结相对路径的基准目录。
2. 只构造本次运行实际需要的对象：训练可包括模型、数据处理器、优化器、损失与调度器；仅推理或分析不要求构造优化器、训练损失或调度器，不适用字段记为 `not_applicable`。
3. 从真实构造对象和运行状态回读可核验值，包括模型维度、模块开关、优化器参数组等；与合并输入交叉核对。不能仅复制 YAML 就称“生效配置”。
4. 在 `resolved_config.yaml` 区分 `requested`（合并输入）、`effective`（对象实际生效值）与 `sources`（来源）。对象不可读取的字段标 `unknown` 并写原因，不猜测内部默认值。
5. 必要配置与实际对象冲突时停止，不产出正式结果。运行中会变化的值在配置中记录初始值及变化规则，并把实际轨迹存到 `raw/`。

历史运行无法回读构造对象时，只登记当时保存的配置、日志或 checkpoint 能证明的值及证据等级。缺字段保持 `unknown`，不补造历史 `effective`。

## 6. 结果隔离与来源

每次运行使用唯一 `run_id`，包括重试、评测或分析重做。创建运行目录时检查不存在并独占创建；发现同名立即停止，不覆盖、清空或合并旧结果。草稿或失败运行保留状态，不伪装成功。


| 文件                   | 必须记录                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `resolved_config.yaml` | 输入配置、真实生效值、字段来源与未核验项。                                                                             |
| `provenance.yaml`      | 运行标识与类型、起止时间、命令及工作目录、实际环境、输入清单、所用 checkpoint 与内容哈希、配置哈希、实际代码快照哈希。 |
| `raw/`                 | 原始日志、预测、指标、训练产物或其他任务所需输出；保留失败与缺失记录。                                                 |
| `analysis.md`          | 指向原始文件的结果解释、汇总方法、实际纳入运行数、限制与待验证判断。                                                   |

来源哈希默认用 SHA-256 并注明算法。代码来源覆盖实际调用的共享代码与实验代码；只有提交号不能代表未提交修改。记录数据/划分/预处理清单与可取得的内容哈希；缺失哈希写明未取得及原因，路径或时间戳不冒充内容哈希。

每个运行目录只由其所属运行写入；写完的原始产物不可覆盖。重新计算派生分析时建立新 `run_id` 并引用原运行，避免新解释覆盖历史。汇总仅纳入协议与来源可对齐的运行；失败、缺失和未知不得用猜测值补齐。

## 7. 保留旧资料与追加状态

既有 Markdown、SVG、实验结果、配置和代码默认保留原样；需要迁移或修改必须另获明确授权。新说明链接旧资料，不重排、改写或替换旧文件。新增文件遇到同名先停止核对，不直接覆盖。

`STATUS.md` 是唯一明确允许在获准范围内追加的已有文档：

1. 追加前读取当前完整字节内容，记录原字节长度与 SHA-256。
2. 写入前再次核对当前文件，发现并发变化则重新读取，不能沿用旧尾部。
3. 只在末尾新增本次状态、证据路径和限制；需要分隔换行时也追加，不改旧末尾字节。
4. 追加后验证新文件前 N 个字节与原内容完全相同，且前缀哈希一致；保留核验结果。

不能通过重新生成整份状态文档来实现“末尾追加”。旧 SVG 的新版本使用新文件名；旧内容与证据链接保留。

## 8. 模型尚未确定时

只交付目录职责、待确认清单和注释型占位文件。`model.py` 不造可运行模型、假 `forward` 或返回常数的实现；`config.yaml` 可为带说明的空映射，不填任意学习率、batch size、维度、seed 或训练轮数。`method.md` 写清未定项，机制图不生成，真实运行目录不建立。

模型确定且用户授权实现后，再补具体接口、代码与必要验证。初始化阶段不安装依赖、不自动下载、不训练、不构造虚构 checkpoint 或结果。

## 9. 初始化交付核验

交付时给出新增文件路径、职责、已确认信息、仍未确定项及实际执行的检查。核查目录一致、公共代码没有复制、创新与注入位置清楚、配置优先级明确、旧资料未改；若获准追加 `STATUS.md`，附原前缀不变的核验结果。

文档检查只证明结构与说明符合约定。没有实际执行就不能声称模型可运行、参数回读正确、图已可编辑或实验可复现；冒烟成功也不代表科学假设成立。正式运行须单独确认范围并遵守目标项目的启动与审查规则。
